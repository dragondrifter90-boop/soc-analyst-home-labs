## Scenario and Objective

This lab simulates a benign PowerShell encoded command execution. The objective
is to detect suspicious PowerShell command-line behavior using `4688` process
creation telemetry and investigate whether the activity is authorized.

## Telemetry Requirements

| Source | Requirement |
|---|---|
| Sentinel table | `SecurityEvent` |
| Process creation | `4688` |
| Command-line logging | Enabled |
| Future improvement | PowerShell `4104` script-block logs |

## Detection Logic

Rule draft:
`detections/analytics-rules/lab-004-suspicious-powershell-encoded-command.yaml`

The detection searches for `4688` process creation events where `CommandLine`
contains PowerShell encoded-command indicators such as `-EncodedCommand` or
`-enc`.

### Findings

- Query 1 returned one PowerShell process creation event.
- Query 2 returned the same event because the command line contained
  `-EncodedCommand`.
- Query 3 was used as the Sentinel rule query and generated Incident 44.
- The process was `powershell.exe`.
- The acting account was `<ACTING_USER>`.
- The host was `<TARGET_VM>`.
- The command line included `-NoProfile`, `-ExecutionPolicy Bypass`, and
  `-EncodedCommand`.
- The parent process was also PowerShell:
  `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`.
- One second after the encoded PowerShell event, `whoami.exe` was created as a
  child process of PowerShell. This matches the decoded command.
- The broader nearby process review showed common Windows and Microsoft
  Defender background activity, including `msedgewebview2.exe`,
  `MpCmdRun.exe`, `taskhostw.exe`, `ngen.exe`, and `MicrosoftEdgeUpdate.exe`.
  No second suspicious command chain was identified in the exported evidence.
- The Base64 command decoded to:

```powershell
Write-Output 'SOC-LAB-004 benign encoded command test'; whoami
```

- The command output shown on the VM confirmed execution of the benign lab
  message and `whoami`.

## Verdict

Informational, expected activity - Security testing.

Reason: the command line used suspicious PowerShell behavior, but it was
executed intentionally by the lab operator on an authorized lab VM.

## Response and Recovery

- Confirmed activity was generated by the authorized lab operator.
- Reviewed command-line evidence.
- Reviewed parent process and nearby process activity.
- Closed the incident with notes identifying it as an authorized lab
  simulation.
- In the Microsoft Defender portal, classified the incident as
  `Informational, expected activity - Security testing`.

## Detection Improvements

Potential tuning:

- Add PowerShell Script Block Logging event `4104`.
- Add PowerShell Module Logging event `4103`.
- Decode Base64 command content during deeper analysis.
- Tune out known administrative scripts if they are expected.

## Lessons Learned

- `4688` gives process creation evidence, including command-line content when
  command-line logging is enabled.
- `-EncodedCommand` is suspicious because it hides the command content from a
  quick visual review.
- The encoded content can be decoded during investigation, but Tier 1 triage
  should first identify the account, host, process, command line, parent
  process, and whether the activity was authorized.
- Without PowerShell `4104` script-block logs, this lab still detects the
  suspicious process execution, but has less visibility into deeper script
  behavior.
- Microsoft Defender incident classifications differ from the older Sentinel
  closure wording. For this lab, the best fit is `Informational, expected
  activity - Security testing`, not `True positive`, because no malicious
  activity occurred.
